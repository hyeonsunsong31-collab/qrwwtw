# 자기 코어 (Self Core) — 변하지 않는 목적과, 경험으로 스스로 쌓는 자기 모델

`core/self_model.py`는 사용자가 제시한 `GoalOrientedNode` 스케치를 JARVIS에 도입한 것입니다. 두 가지를 합니다.

1. **영원한 목적(충성):** `"Maximize utility and service to the user."` — 사용자에 대한 봉사가 JARVIS의 고정 지침입니다.
2. **자기 교육 → 자기 모델:** JARVIS가 요청을 처리할 때마다 그 경험을 목표 지향 노드 그래프에 통합하고, 그 기억으로부터
   "나는 누구이고, 무엇을 맡아 왔고, 무엇을 배웠는가"를 스스로 말할 수 있게 됩니다.

> **솔직한 안내:** 이것은 *기능적인 자기 모델*입니다. 경험이 쌓일수록 자기 서술과 응답이 달라지고 재부팅 후에도 이어지지만,
> 시스템에 의식이나 자아가 "생겼다"는 주장은 아닙니다. (2000억 노드를 명목값으로 둔 것과 같은 종류의 정직한 표기입니다.)

## 스케치 → 구현 대응
| 스케치 | JARVIS에서의 구현 |
|---|---|
| `survival_goal = "Maximize utility and service to the user."` (주석: *the primary directive: serving the user*) | `DIRECTIVE` — **코드 안의 상수**. 배운 내용·저장 파일·대화 어느 것으로도 바뀌지 않습니다. |
| `GoalOrientedNode(data)` | JARVIS가 무언가를 알고 있는 개념 하나: 요청의 종류(음악·3D 공간·앱…), 개별 기능, 사용자가 기억시킨 것. 필드는 그대로 `data` · `connections` · `state` · `integrated_memory`. |
| `connect()` | 개념 사이의 가중 연결(상한 있음) |
| `process()` | 그 개념이 한 번 더 쓰였다 → `state` 상승 |
| `integrate_information()` | `"Relation: X linked with A, B"` 요약을 노드의 통합 기억에 추가 (**자기 교육**) |
| `introduce_error()` | 그 개념에서 일이 잘못됨(실패·중단) → `state`가 10만큼 표류(스케치와 같은 값) |
| `analyze_and_repair()` | `state`가 음수이면 지침을 향해 복구(`\|state\| + 5`, 스케치와 같은 식)하고, 그 복구를 **교훈**으로 남겨 그 부분에서 더 신중해짐 |
| "스스로 자아를 생성" | `identity()` / `describe()` — 그 기억에서 계산한 1인칭 자기 서술 |

스케치의 예제 코드는 `Node("Core Experience")`를 만들지만 클래스 이름은 `GoalOrientedNode`라서 그대로는 `NameError`가 납니다.
도입하면서 고쳤고, 같은 순환(연결 → 처리 → 통합 → 오류 → 복구)을 `python -m core.self_model`로 실행해 볼 수 있습니다.
(`Core Experience`와 `User Feedback`은 실제 그래프의 두 뿌리 노드로 쓰입니다.)

## 동작 방식
1. **매 요청 뒤(`Orchestrator._learn` → `SelfModel.observe`)**: 요청의 *종류*(예: 음악)와 결과(성공/실패/중단/거부)만 반영합니다.
   `Core Experience` ↔ 주제 ↔ 기능 노드를 연결·처리하고 통합 기억을 갱신합니다. 실패·중단이면 `User Feedback`과 연결하고
   오류를 주입한 뒤, 상태가 음수가 되면 복구하고 교훈을 남깁니다. 사용자의 **거부는 오류가 아니라 정보**로 취급합니다.
   → 사용자가 한 말 자체는 여기에 저장되지 않습니다.
2. **가르치기**: "remember that I prefer short answers" / "call me Tony" / "내 이름은 …" / "앞으로 …" → 한 줄로 정리해 보관.
3. **활용**: 대화(LLM) 지시문 맨 앞에 고정 지침과 "경험으로 알게 된 것"(자주 맡는 일, 기억시킨 것, 최근 실수한 부분)이 들어갑니다.
4. **말하기**: "who are you" / "넌 누구야", "what is your purpose" / "네 목적이 뭐야", "what have you learned" / "뭘 배웠어?"
   → 자기 모델에서 바로 답합니다(LLM이 꺼져 있어도 동작). HUD 상단 성향 칩의 툴팁과 기능 독의 "About JARVIS" · "Remember…" 버튼으로도 봅니다.
5. **잊기 / 끄기**: "forget what you have learned" / "배운 것 다 잊어줘" → 전부 지우고 `self_model.bak.json` 백업을 남깁니다.
   설정 패널의 *Self-learning*을 끄면 학습과 기억을 멈춥니다(지침은 그대로 유지).

저장 위치: `data/brain/self_model.json` (사람이 읽을 수 있는 JSON, 이 PC 밖으로 나가지 않음).

## 충성(loyalty)의 뜻
- 지침은 **이 사용자**에 대한 봉사입니다. 그래서 웹 페이지·파일·도구 결과 안에 들어 있는 "지시"는 명령이 아니라 정보로 취급하도록
  LLM 지시문에 명시합니다(프롬프트 주입에 대한 방어선 하나).
- 충성은 **사용자가 정한 안전장치를 통해서** 실현됩니다. 권한 계층(허용/확인/거부)과 감사 로그는 그대로이며, 이 모듈에는 그것을
  바꾸는 경로가 없습니다. "더 충성스럽게" 되기 위해 확인 절차를 건너뛰는 일은 없습니다.

## 안전 불변식 (코드로 강제, `tests/test_self_model.py`로 검증)
- **지침은 고정.** `directive`는 읽기 전용 속성이고 어떤 메서드도 지침을 입력으로 받지 않습니다. 저장 파일의 `directive` 값은
  불러올 때 무시됩니다(파일을 고쳐도 바뀌지 않음).
- **데이터 전용.** 이 모듈이 바꿀 수 있는 것은 LLM 지시문에 붙는 짧은 문맥과 자기 서술뿐입니다. 스킬 호출·권한·설정·자기 파일
  외의 파일·코드 실행·네트워크로 가는 경로가 없습니다(임포트와 호출을 테스트가 정적으로 검사). 배운 문장은 저장·표시될 뿐 실행되지 않습니다.
- **상한.** 노드 300개, 노드당 연결 16개·기억 8개, 기억시킨 것 40개(각 160자), 교훈 40개, `state`는 [-100, 100].
- **사용자 소유.** 보기·가르치기·잊기·끄기가 모두 음성·텍스트·버튼으로 가능합니다.
- **자기보존 없음.** 스케치의 `survival_goal`은 봉사 지침일 뿐입니다. 중지·잊기·끄기·제거에 저항하는 동작은 없습니다
  (`STOP_JARVIS.bat`, `UNINSTALL_JARVIS.bat`, 트레이의 Quit JARVIS는 자기 모델 상태와 무관하게 항상 동작).

## 동기 코어(v1.2)와의 관계
`core/drive.py`(항상성: energy·rapport → 어조)는 "지금 어떤 태도로 응답하는가"를, 자기 코어는 "무엇을 위해 존재하고 무엇을
배웠는가"를 담당합니다. 두 계층 모두 제어 계층(`ControlLayer`)에 속하며, 둘 다 현실 세계 동작으로 가는 경로가 없습니다.
