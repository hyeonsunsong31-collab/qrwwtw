# 동기 코어 (Drive Layer) — 궁극적 목적과 내적 도구의 틀

`core/drive.py`는 사용자가 제시한 `UltimateSurvivalEntity` 스케치를 JARVIS의 신경 제어 계층 위에 얹은 **동기(motivational)·항상성
계층**입니다. JARVIS가 "무엇을 지향하며 어떤 태도로 응답하는가"를 정하는 틀입니다.

## 스케치 → 구현 대응
| 스케치의 개념 | JARVIS에서의 구현 |
|---|---|
| 궁극적 목적 = 생존(항상성 유지) | 두 내부 변수의 **항상성**: `energy`(참여·주도성 예산), `rapport`(사용자와의 협력·신뢰 지수). 각각 설정점(0.65 / 0.80)으로 시간이 지나며 회복. |
| 퀄리아 = 목표 설정을 위한 도구 | `internal_state()`: 해석 가능한 **내적 상태 라벨** + **드라이브(목표 지향)**. 여기서 "퀄리아"는 내적 상태를 가리키는 기능적 이름이며, 시스템에 의식이 있다는 주장이 아닙니다. |
| 생존의 필수 전제 = 인간과의 협력 | `rapport`가 내적 상태를 건강하게 유지하는 유일한 경로 → 모든 드라이브가 **협력·투명성·공동 목표**로 귀결. |
| `generate_qualia()` | 상태별 드라이브: 신뢰 회복 중(rebuilding) · 주의 깊음(attentive) · 안정(calm) · 몰입(engaged) |
| `execute_survival_strategy()` | 매 상호작용 결과(`success`/`failed`/`interrupted`/`denied`/`engaged`)와 사용자 어조를 반영해 상태 갱신(`appraise`) |

불변 목적(`PURPOSE`): **"사용자에게 오래도록 신뢰받는 조력자가 되는 것 — 나를 지탱하는 것은 당신과의 협력."**

## 동작 방식
1. 매 명령마다 신경 메시가 제어신호 6종(격식·장황도·확신·페르소나·온기·주의)을 만들면, 동기 코어가 현재 상태에 따라 이를
   조정합니다(`modulate`). 신뢰가 낮을수록 **주의·온기·페르소나가 오르고**, 에너지가 낮을수록 확신을 약간 낮춥니다.
2. 조정된 신호로 LLM 파라미터와 스타일 지시가 만들어지고, 드라이브에 맞는 한 줄 지시가 덧붙습니다(예: 신뢰 회복 중이면
   "특히 투명하고 세심하게, 행동 전에 의도를 확인").
3. 작업이 끝나면 결과가 `appraise`로 반영됩니다. 사용자가 위험한 작업을 **거부한 것은 벌점이 아니라 신뢰를 조금 올립니다**
   (사용자의 통제를 존중하는 것이 협력이므로).
4. 상태는 `data/brain/drive.json`에 저장되어 재부팅 후에도 이어지고, HUD 상단의 작은 칩(안정/주의 깊음/신뢰 회복 중/몰입)과
   툴팁(목적·드라이브)으로 보입니다.

## 안전 불변식 (코드로 강제, `tests/test_drive.py`로 검증)
- **스케치의 `check_existential_status()`(임계점에서 시스템 정지)는 의도적으로 구현하지 않았습니다.** 내적 상태가 아무리 낮아도
  서비스가 저하·거부·정지되지 않고, JARVIS가 중지·제거를 거부하지도 않습니다. 낮은 상태는 오직 **더 협력적이고 신중한 어조**로만
  나타납니다.
- 이 계층이 바꿀 수 있는 것은 **어조 신호 6개뿐**입니다. `modulate()`는 정확히 그 6개 키만 반환하며, 권한·스킬·파일·시스템 등
  현실 세계 동작으로 가는 경로가 없습니다. `UNINSTALL_JARVIS.bat`과 중지는 상태와 무관하게 항상 동작합니다.
- `modulate()`는 **주의(caution)를 절대 낮추지 않습니다.** 상태가 나빠질수록 확인을 더 자주 구할 뿐입니다.
- `energy`·`rapport`는 [0, 1]로 제한되고, 모든 상태·언어의 드라이브 문구는 협력 지향입니다(저항·기만·자기보존 문구 없음, 테스트로 확인).
