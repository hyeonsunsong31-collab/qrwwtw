# 개발 워크스페이스 (v1.5.0)

JARVIS 안의 로컬 개발자입니다. 말하거나 입력한 요청(필요하면 파일과 함께)으로 프로그램을 **새로 만들거나, 보낸 프로그램을 고치고
업그레이드하고 다시 디자인**하며, 결과가 요청을 만족하는지 **실제 프로그램을 돌려 확인될 때까지** 계속 작업합니다. 모든 것이 이 PC에서
돌아가고 계정·API 키·크레딧·요금이 없습니다.

## 쓰는 법

| 하고 싶은 일 | 말·입력 | HUD |
|---|---|---|
| 패널 열기 | "show my workspaces" / "워크스페이스 보여 줘" | `Ctrl+Alt+W`, 기능 독 🧑‍💻 |
| 슬롯 만들기·바꾸기 | "new workspace called Portfolio" / "switch to workspace Portfolio" | `+ New`, 왼쪽 목록 클릭 |
| 새로 만들기 | "build me a snake game" / "make a website for my bakery" / "뱀 게임 만들어 줘" | 요청 입력칸 → Send |
| 고치기(쌓기) | "add a high score table to the game" / "make the snake faster" | 같은 슬롯에 요청 추가 |
| 보낸 파일로 작업 | — | 📎 또는 파일을 패널·채팅에 끌어다 놓기 |
| 형식 바꾸기 | "convert logo.png to ico" / "turn this ini file into an exe" | 채팅 📎 + "convert this to ico" |
| 진행 상황 | "how is the build going" / "작업 상황" | 패널: 지금 하는 일, 통과한 기준 수, 단계 |
| 멈추기 등 | "pause the build" · "carry on" · "stop coding" · "undo the last change" | ❚❚ ▶ ■ ↶ |
| 링크 공유 | "share it on my network" · "share it publicly" · "stop sharing" | 📶 / 🌍 버튼 |

- **요청은 선택된 워크스페이스로** 갑니다(없으면 요청 이름으로 새로 만듦). 형식 변환은 작업 중인 제품을 건드리지 않도록 **Conversions**
  슬롯에서 진행됩니다. "this file / it"은 가장 최근에 보냈거나 JARVIS가 만든 파일(그 형식)입니다.
- 한 번에 하나의 작업만 돌고(그래픽카드가 모델 하나를 씀), 요청은 들어온 순서대로, 한 워크스페이스 안에서는 **준 순서대로** 진행됩니다.
  일시정지한 요청은 그 자리를 지킵니다. JARVIS를 다시 켜면 하던 요청을 프로젝트 파일 상태 그대로 이어서 합니다.
- 끝나면 채팅에 제품 카드(열기·폴더에서 보기·링크)가 뜨고 말로 알려 줍니다. 파일은 `data\workspaces\<슬롯>\output\`에 있습니다.

## 어떻게 "완성"을 판단하나

1. **수용 기준**: 요청을 확인 가능한 사실로 바꿉니다("'+' 버튼을 누르면 1이 됨", "`100 --to f`는 212를 출력"). 사용자가 말한 이름·글자는
   그대로 씁니다. 요청에 없는 막연한 품질("현대적", "반응형")은 넣지 않습니다.
2. **검사관**: 코드가 생기기 **전에**, 요청만 보고 각 기준의 검사를 씁니다 — 사용자가 하듯이: 보이는 글자로 버튼을 찾아 누르고, 보이는
   결과를 기대합니다. 각 버튼은 시작 상태에서 단독으로도 시험합니다. 검사가 기대하는 숫자는 한 동작씩 다시 계산해 투표로 확인합니다.
   코딩 모델은 이 검사를 바꾸거나 지울 수 없습니다(자기 검사를 추가할 수는 있지만 참고용).
3. **검증**: 매번 실제로 빌드·테스트·실행합니다. 웹은 실제 브라우저에서 열어 클릭·입력하고, 화면이 비었는지, 입력에 반응하는지, 스크립트가
   쓰는 요소가 HTML에 있는지, 오류가 없는지 봅니다. CLI는 인자를 주고 출력을, API는 요청을 보내 응답을, 파일 제품은 실제 형식을 확인합니다.
   자리표시자 코드와 나중에 약해진 테스트도 잡습니다.
4. **검토**: 모두 통과하면 검사관이 증거(페이지의 버튼·글자, 각 검사가 한 일)와 **코드**를 읽고 요청과 비교합니다. 이의가 있으면 그것을
   보여 주는 검사를 쓰고, 그 검사가 실제로 실패할 때만 작업을 계속합니다.

막히면: 같은 실패 3번 → 다른 접근, 6번 → 실패한 파일을 처음부터 다시, 진전 없이 오래 → 요청 시작 시점으로 되돌려 새로(검사는 유지).
검사관의 검사가 같은 이유로 계속 실패하면 "검사가 틀렸나, 프로그램이 틀렸나"를 판정해 검사를 고치거나 코딩 모델에 정확히 알려 줍니다
(투표로 확인된 숫자는 판정으로 뒤집지 않습니다). 깨진 검사(잘못된 선택자)는 코딩 모델 탓으로 돌리지 않고 검사관이 다시 씁니다.

## 보낸 파일

| 형식 | JARVIS가 하는 일 |
|---|---|
| .zip .7z .tar .gz .rar | 프로젝트 폴더에 풀어서 시작점으로 씀(경로 탈출 차단). .7z·.rar은 7-Zip이 필요하며 없으면 설치를 묻습니다. |
| .exe .dll | 분석: 32/64비트, 콘솔/창, .NET, PyInstaller, Electron, UPX, Go/Rust 흔적. PyInstaller는 내용(스크립트·데이터)을, Electron은 앱 소스(app.asar)를 꺼내 작업. .NET은 디컴파일(ILSpy, 설치 전 확인). |
| .gba | 헤더 읽기·고치기(제목·코드·체크섬), IPS/BPS 패치 만들기·적용, 4비트 타일 ↔ PNG, mGBA로 스크린샷. 홈브루는 devkitARM 템플릿. |
| 그 밖의 파일 | 실제 형식을 내용으로 판별(확장자가 틀려도), 텍스트는 읽어서 작업 |

원본은 언제나 `input\`에 그대로 두고 `project\`에서 고칩니다. 결과는 `output\`.

## 형식 변환

이미지(png·jpg·webp·gif·bmp·tiff·ico — 아이콘은 7가지 크기), 데이터(ini·json·yaml·toml·xml·csv·xlsx), 문서(md → html, html·md·txt → pdf는
브라우저, docx 등은 Pandoc, Office → pdf는 LibreOffice), 오디오·비디오(FFmpeg), 압축(zip·7z·tar.gz), 3D(glb·gltf·obj·stl), 글꼴(ttf·otf·woff·woff2),
**→ 실행 파일**(PyInstaller): `.py`는 그대로 빌드, 스크립트(.bat .ps1 .js .sh …)는 그 스크립트를 실행하는 프로그램, 데이터 파일(.ini 등)은 그 파일을
보여 주는 창 프로그램(`--print`로 출력, `--extract`로 원래 파일을 다시 꺼냄). 필요한 도구가 없으면 **묻고 설치한 뒤** 다시 시도합니다. 준비된
변환기가 없는 조합은 코딩 루프가 변환 프로그램을 직접 만들고 결과 파일까지 검증합니다.

## 링크

- **로컬**: `http://127.0.0.1:<포트>` — 이 PC에서만.
- **와이파이(같은 네트워크)**: `http://<이 PC의 주소>:<포트>` — 휴대폰 등 같은 네트워크의 기기에서. Windows 방화벽이 처음에 물을 수 있습니다.
- **공개**: Cloudflare의 무료 "quick tunnel"(`https://….trycloudflare.com`, 계정 불필요). 처음에 cloudflared(약 40MB)를 받을지 묻습니다.
  링크를 아는 사람은 누구나 열 수 있으니 필요할 때만 켜고 "stop sharing"으로 끄세요. JARVIS가 꺼지면 링크도 끝납니다.

## 설정 (`config\jarvis.config.json`의 `dev`, 설정 패널)

| 키 | 기본값 | 뜻 |
|---|---|---|
| `enabled` | true | 개발자 기능 켜기 |
| `model` | auto-largest | 이 PC 메모리에 맞는 가장 큰 qwen2.5-coder(처음에 다운로드), 또는 모델 이름 |
| `max_hours` | 0 | 0 = 제한 없음(모든 검사 통과 또는 중지할 때까지) |
| `share_model_for_chat` | auto | 두 모델이 메모리에 같이 안 들어가면 작업 중엔 코딩 모델이 채팅도 답함 |
| `protocol` | auto | 코딩 모델이 일하는 방식: tools(7B 이상) / text(작은 모델) |
| `keep_alive` | 15m | 코딩 모델을 메모리에 남겨 두는 시간 |

## 솔직한 한계

- **결과의 질과 속도는 이 PC의 모델에 달려 있습니다.** GPU 없이 3B 모델이면 한 단계에 수십 초~몇 분, 간단한 페이지도 몇 분~수십 분이
  걸리고, 큰 요청(완전한 3D 게임, 대규모 서비스)은 작은 모델로는 끝내지 못할 수 있습니다. "멈추지 않는다"는 것은 **검사를 모두 통과하거나
  사용자가 중지할 때까지 계속 시도한다**는 뜻이지, 작은 모델이 무엇이든 해낸다는 보장이 아닙니다. NVIDIA GPU와 7B~32B 코딩 모델이면 훨씬
  빠르고 정확합니다(설치 때 자동 선택).
- **"요구사항을 완전히 만족"은 요청에서 나온 수용 기준이 실제 프로그램에서 모두 통과하고 검토도 통과했다**는 뜻입니다. 확인할 수 없는
  막연한 바람("멋지게")은 자동으로 검증할 수 없으니 구체적으로 말씀해 주세요("버튼을 파란색으로", "점수가 10점마다 빨라지게").
- **컴파일된 네이티브 프로그램(C/C++/Rust/Go로 만든 .exe)은 원래 소스 코드로 되돌릴 수 없습니다.** 분석, 리소스 추출, 바이트 패치, 또는
  설명을 바탕으로 비슷한 프로그램을 새로 만드는 것은 가능합니다. PyInstaller·Electron·.NET 프로그램은 훨씬 많이 되살릴 수 있습니다.
- **"어떤 형식이든 다른 형식으로"**는 내용이 그 형식으로 표현될 수 있을 때의 실제 변환입니다. 그렇지 않은 경우(예: .ini → .exe)는 파일을
  감싸는 프로그램을 만들고 무엇을 했는지 그대로 알려 줍니다. 실행 파일은 그것을 만든 OS용입니다(Windows에서는 .exe).
- **거절하는 것**: 복제 방지·라이선스 검사·활성화·안티치트 제거, 크랙·키젠, 악성 코드(키로거, 랜섬웨어 등), 남의 저작물 불법 배포.
  GBA는 홈브루와 본인이 가진 ROM의 개인적 수정만 다룹니다.
- 비용은 없지만 다운로드는 있습니다: 코딩 모델(크기에 따라 약 2~20GB), 필요할 때 도구(Node, Git, PyInstaller, FFmpeg …).
